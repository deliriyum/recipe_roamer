You are adding three interconnected features to RecipeRoamer: a Weekly Meal 
Planner, a Smart Shopping List, and a Pantry tracker. The app uses React 18 + 
Vite frontend, Express/Node backend, Drizzle ORM, PostgreSQL (Neon serverless), 
shadcn/ui, TanStack Query v5, React Hook Form + Zod, and has OpenAI API access.

CRITICAL CONTEXT: The recipes table schema exists in Drizzle but recipe CRUD 
routes and storage methods are NOT yet implemented. Wire those up as part of 
this feature addition — all three new features depend on real recipe data.

PART 1: DATABASE SCHEMA — NEW TABLES
════════════════════════════════════════════

Add these tables to the Drizzle schema and run migration:

REPLACE the existing `ingredients TEXT[]` column in the recipes table with 
a separate junction table:

recipe_ingredients
├── id               UUID    PRIMARY KEY DEFAULT gen_random_uuid()
├── recipe_id        UUID    FK → recipes.id (CASCADE DELETE)
├── ingredient_name  TEXT    NOT NULL    (e.g. "flour")
├── quantity         REAL    NULLABLE    (e.g. 2.0)
├── unit             TEXT    NULLABLE    (e.g. "cups")
└── notes            TEXT    NULLABLE    (e.g. "sifted", "room temperature")

Update the recipe import pipeline, URL scraper, and OCR upload to parse 
ingredients into structured fields at IMPORT TIME using OpenAI:
  - Parse freeform strings like "2 cups flour, sifted" into:
    { ingredient_name: "flour", quantity: 2.0, unit: "cups", notes: "sifted" }
  - This means shopping list consolidation and pantry cross-referencing 
    can do real math instead of string parsing at generation time
  - Update all recipe GET endpoints to JOIN recipe_ingredients and return 
    them as a structured array on the recipe object
  - Update recipe display components to render from the new structure

meal_plans
├── id           UUID    PRIMARY KEY DEFAULT gen_random_uuid()
├── week_start   DATE    NOT NULL  (Monday of the planned week)
├── created_at   TIMESTAMP DEFAULT now()
└── updated_at   TIMESTAMP DEFAULT now()

meal_plan_entries
├── id              UUID    PRIMARY KEY DEFAULT gen_random_uuid()
├── meal_plan_id    UUID    FK → meal_plans.id (CASCADE DELETE)
├── day_of_week     INTEGER NOT NULL  (0=Monday … 6=Sunday)
├── meal_slot       TEXT    NOT NULL  (breakfast | lunch | dinner | snack)
├── recipe_id       UUID    FK → recipes.id (SET NULL on delete) NULLABLE
├── custom_meal     TEXT    NULLABLE  (freeform text if no recipe linked)
└── servings_override INTEGER NULLABLE (override recipe default servings)

shopping_lists
├── id            UUID    PRIMARY KEY DEFAULT gen_random_uuid()
├── meal_plan_id  UUID    FK → meal_plans.id NULLABLE 
│                         (null = standalone list)
├── name          TEXT    NOT NULL DEFAULT 'Shopping List'
├── created_at    TIMESTAMP DEFAULT now()
└── updated_at    TIMESTAMP DEFAULT now()

shopping_list_items
├── id                UUID    PRIMARY KEY DEFAULT gen_random_uuid()
├── shopping_list_id  UUID    FK → shopping_lists.id (CASCADE DELETE)
├── ingredient_name   TEXT    NOT NULL
├── quantity          REAL    NULLABLE
├── unit              TEXT    NULLABLE
├── category          TEXT    NULLABLE  (produce | dairy | meat | pantry | etc.)
├── is_checked        BOOLEAN DEFAULT false
├── is_manual         BOOLEAN DEFAULT false  (manually added vs auto-generated)
├── source_recipe_id  UUID    FK → recipes.id NULLABLE
└── notes             TEXT    NULLABLE

pantry_items
├── id              UUID    PRIMARY KEY DEFAULT gen_random_uuid()
├── ingredient_name TEXT    NOT NULL
├── quantity        REAL    NULLABLE
├── unit            TEXT    NULLABLE
├── category        TEXT    NULLABLE
├── expiry_date     DATE    NULLABLE
├── added_at        TIMESTAMP DEFAULT now()
└── updated_at      TIMESTAMP DEFAULT now()

PART 2: BACKEND — API ROUTES & STORAGE
════════════════════════════════════════════

Implement full CRUD storage methods and Express routes for all new tables.

MEAL PLAN ROUTES:
  GET    /api/meal-plans                    → list all meal plans
  GET    /api/meal-plans/:id                → single plan with entries + recipes
  GET    /api/meal-plans/week/:weekStart    → plan for a specific week (YYYY-MM-DD)
  POST   /api/meal-plans                    → create new meal plan
  POST   /api/meal-plans/:id/entries        → add entry to plan
  PUT    /api/meal-plans/:id/entries/:entryId → update entry (recipe, slot, servings)
  DELETE /api/meal-plans/:id/entries/:entryId → remove entry

SHOPPING LIST ROUTES:
  GET    /api/shopping-lists                → list all shopping lists
  GET    /api/shopping-lists/:id            → single list with items
  POST   /api/shopping-lists                → create new list
  POST   /api/shopping-lists/generate       → generate from meal plan (see below)
  PUT    /api/shopping-lists/:id/items/:itemId → update item (check/uncheck, qty)
  POST   /api/shopping-lists/:id/items      → add manual item
  DELETE /api/shopping-lists/:id/items/:itemId → remove item
  DELETE /api/shopping-lists/:id/checked    → clear all checked items

SHOPPING LIST GENERATION ENDPOINT (POST /api/shopping-lists/generate):
  - Accepts: { mealPlanId, servingsMultiplier? }
  - Collects all ingredients from all recipes in the meal plan
  - Adjusts quantities by servings_override vs recipe default servings
  - Uses OpenAI API to parse and consolidate ingredient strings:
      Prompt: "Parse these ingredient strings and consolidate duplicates. 
      Return JSON array of: { ingredient_name, quantity, unit, category }.
      Combine identical ingredients (e.g. '2 cups flour' + '1 cup flour' = 
      '3 cups flour'). Normalize units (tbsp→tablespoon, etc). 
      Categorize each item as one of: produce, dairy, meat, seafood, 
      bakery, pantry, frozen, beverages, spices, other."
  - Cross-reference against pantry_items: if pantry has sufficient 
    quantity, mark item as is_checked=true with a note "In pantry"
  - Creates shopping_list record linked to meal_plan_id
  - Returns full shopping list with items

PANTRY ROUTES:
  GET    /api/pantry                        → list all pantry items
  POST   /api/pantry                        → add item to pantry
  PUT    /api/pantry/:id                    → update item (qty, expiry, etc.)
  DELETE /api/pantry/:id                    → remove item
  POST   /api/pantry/bulk-add               → add multiple items at once
  POST   /api/pantry/from-shopping-list     → accepts array of shopping_list_item 
                                              ids, moves checked items to pantry
